# Task D: 天然黒鉛の公開経路

基点: main `4fedb0b`。2026-09-14にプロジェクト所有者が「鉱山生産を公開、
貿易は確認中にする」と回答した方針を実装する。監査全体の `publishable: false`
を書き換えて公開する方式にはしない。独立監査は引き続き未公開判定を保持する。

## 公開する範囲

- USGS MCS 2019〜2026の固定版による2017〜2024年の天然黒鉛鉱山生産。
- 既存の目視レビュー済み8 PDFをSHA256で検証し、表を再抽出して計算する。
- 国別値・原トークン・推計区分・資料の版・原本ハッシュを公開JSONに保持する。
- Otherを国としてHHIに入れない。ゼロと欠測を保持し、世界合計の丸め差を公開する。
- 2018、2020、2022の変動フラグを保持。異なる版・収録国による変化を含むことを
  明記し、自動の成長率／集中度増減コメントは表示しない。
- 貿易は日英で「確認中」。輸出額・重量のいずれのHHIも生成しない。
  `trade-status.json` は件数と保留理由のみで、未解決の選択標本を指標として掲載しない。

## 実行と失敗時の動作

```sh
python -m pipeline.publish_graphite
python -m pipeline.build --only natural-graphite
python -m pytest pipeline/tests -q
python -m pipeline.render
```

通信・APIキー不要。既存のComtrade Rawをハッシュ検証・再正規化し、全32クエリの
年／HS／方向、重複キーを検査する。USGSは一時領域にコピーして再抽出する。
`pipeline/graphite_publication.json` は対象年、レビューした原数値のダイジェスト、
変動フラグ年と公開範囲を固定する。新しい年・原数値・推計区分・フラグは再レビューが必要。
確認済みデータと新しい原本を自動で混ぜない。更新日時を再実行のたびに変えない。

一時領域で公開JSONと全HTMLを生成し、レンダリング成功後に変更ファイルだけを反映する。
ファイル置換失敗時は既存の共通ロールバック処理を使用する。原本破損、判定不一致、
レンダリング失敗は非ゼロ終了し、前回公開ファイルを保持する。
`--fixtures` は従来のレイアウト用経路のまま。公開処理はfixturesサイトへの書込みを拒否する。

既存の監査Actionsは監査専用のまま。公開はレビュー済みコミットをmainへマージした後の
既存Pagesフローで行う。CIにRaw再現と公開JSONのstaleチェックを追加した。

## 実データと設計上の違い

天然黒鉛をリチウムの選択ポリシーへ渡すだけでは公開できなかった。既存監査は
23,458貿易観測、1,384判定のうち1,356が未解決で、全年度・HSの選択標本が公開基準未達。
ミラー差異を自動で大きい方に置換したり、鉱山生産量から輸出重量を推定したりしない。
このため、鉱山と貿易を別々に公開判定する専用publisherを追加した。

公開系列キーは `mine_natural_graphite_t`、単位は `t natural graphite`。
USGS原表の推計を `status: estimated` のまま保持する。外部照合による採用変更では
ないため、`selected_source: reported`、`verification_status: not_applicable` とする。
これは推計値を確定値と呼ぶ意味ではない。既存5値enumは拡張しない。
リチウムの `mine_li_t`、単位、分類、選択規則、公開データは移行しない。

## 検証

追加回帰検証は原監査と8年のHHI/CR3・国別シェア一致、原数値／推計区分の変更拒否、
公開方針・年度・品質フラグ変更拒否、fixtures拒否、旧buildからの厳格経路へのルーティング、
原本再生、冪等性、日英の保留表示、ダウンロード先の存在、レンダリング失敗とPDF破損時の
前回公開値保全を対象とする。ローカルで既存を含む225テストが成功（Python 3.14.7）。
公開処理の再実行は変更なし。既存の他鉱物index要約とリチウム公開JSONは不変。
Windowsの初回テストは一時ディレクトリ未作成でsetupエラーとなり、作成して再実行した。
CIのPython 3.12による結果と再レンダリングstaleチェックはPRで別途確認する。
